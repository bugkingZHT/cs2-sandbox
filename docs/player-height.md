# 玩家高度与圆大小

玩家圆的基础尺寸在相同设置百分比下放大 10%，100% 的显示值及已保存的滑块百分比不变。方向三角、描边和随身图标同步放大，字体大小不变。

设置的“地图显示”区域提供“高度缩放效果”开关，默认开启并记住选择。关闭后只取消下面的高度系数，仍使用放大后的基础尺寸、现有大小滑块和地图比例换算；暂停时切换也会立即更新。

玩家圆继续按世界单位换算地图像素，并叠加现有大小滑块与地图缩放。高度效果以所在层参考平面为界，上方最多放大 46%，下方最多缩小 12%。令 `h = 玩家脚下 Z − 所在层参考 Z`：

- `h ≥ 0`：`1 + 0.46 × tanh(h / 128)`
- `h < 0`：`1 + 0.12 × tanh(h / 512)`

各层参考位置的系数均为 1，所以主图和下层在各自基准地面上具有相同的基础世界半径。相对地面越高越大、越低越小，范围为基础大小的 88%–146%。高于基准 128 世界单位约放大 35%，低于基准 128 世界单位约缩小 3%；经过参考平面时大小连续。基准继续按地图层计算，不按个人出生位置校准。方向三角、标记描边和随身图标同步调整；玩家名字与射击线长度不受高度影响。

实现完全在前端，直接读取现有回放帧中的 `z`，不修改解析器、元数据或缓存文件，不需要重新解析 Demo。参考平面不使用世界坐标零点，也不使用分层阈值。

前端从已加载回合中提取存活玩家连续至少 250ms、高度波动不超过 4 世界单位的稳定位置，以持续时间作为权重，避免短暂跳跃、死亡和重复时间帧影响基准。再按地图已有的 `zLayerThreshold` 分组，与主图/下层位置投影使用同一规则（Z 等于阈值时属于下层），分别计算加权中位数作为参考平面。单层地图只计算一个参考平面。

各层首次得到有效基准后，在本次回放中固定，不随当前帧、回合、隐藏玩家或地图缩放改变。初次加载的回合没有某层有效样本时，该层保持基础大小，之后加载有有效样本的回合时再独立校准；不借用另一层的地面高度。切换 Demo 或地图时重新校准。这是从已有 Z 数据估计的显示基准，不是地图几何模型中的绝对海拔。

验证包含零点、负高度、高海拔地图、独立楼层基准、阈值边界、稳定样本筛选、缺失数据、缩放幅度限制和实际 Pixi 图形尺寸。可直接用已经解析好的 Nuke 回合 JSON 测试：

```powershell
$env:CS_HEIGHT_ROUND_FILE = 'C:\path\to\cached-demo\1.json'
cd frontend
node test-player-display.mjs
```
