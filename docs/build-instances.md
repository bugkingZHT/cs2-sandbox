# 多版本 EXE 实例

每个 EXE 的 UID 是整个文件的 SHA-256。`build-local.ps1` 每次打包注入一个新的构建标识，即使代码未变，两次独立打包也有不同 UID。复制或重命名同一份 EXE 不改变 UID。

“系统选项 → 版本信息”独立展示当前版本和 UID 前 16 位，与进程名后缀一致。页面内容使用英文，小号“copy”文字按钮复制完整 UID，由当前运行的后端提供，与 EXE 文件摘要一致；不再放在地图设置中。

首次启动会将经过校验的 EXE 副本放到 `%LOCALAPPDATA%\cs2-sandbox-runtime\<完整 UID>\`，启动 `cs2-sandbox-<UID 前16位>.exe` 后，原始启动器退出。运行中的进程名因此可以在任务管理器中区分，用户可以结束指定旧版本；不会自动结束其他版本。

Windows 内核事件以完整 UID 命名。同一 UID 的再次启动只通知现有进程打开其页面，临时启动器退出；不同 UID 使用独立的事件和进程。程序直接监听 `127.0.0.1:0`，由内核分配当前可用的端口，没有“先查空闲端口、再尝试绑定”的竞态。`-listen` 仅供诊断时显式覆盖。

运行目录中的 `instance.json` 记录完整 UID、PID 和监听地址，不包含页面认证令牌。该文件用于定位进程；是否已有实例只由内核对象决定，所以强制结束进程后不会被遗留 PID 文件阻止重启。结束进程后可手动清理其对应运行目录以回收 EXE 副本占用的空间。

## 共享 Demo 库

所有构建继续使用 `%LOCALAPPDATA%\cs2-sandbox\`，不复制历史缓存。列表和回放请求刷新磁盘索引；跨进程的短时写入锁保护去重、重命名、删除及解析结果提交。新版共同持有旧锁文件的共享句柄，阻止旧版在新版运行期间成为不受协调的写入者。每个解析进程持有内核释放的会话锁，其他构建不会清理其待处理输入，也不会把活跃任务误报为中断。只有任务所属进程退出后，下一次索引刷新才恢复遗留任务。

如果此前的旧 EXE 尚未升级，它仍会独占整个数据目录。新版允许启动和查看历史库，但写入会提示关闭旧进程；旧进程退出后，当前新版无需重启即可写入。所有支持该机制的新版之间可以正常共享写入。解析中的 Demo 可由所属版本重命名，其他版本需等解析完成。

## 验证

常规测试：`go test -mod=vendor ./cmd/local ./pkg/localapp`。

实际 EXE 测试使用独立临时用户缓存，不访问用户现有 Demo 库。在 PowerShell 中设置两份不同构建的绝对路径后执行：

```powershell
$env:CS_INSTANCE_EXE_A = 'C:\path\build-a.exe'
$env:CS_INSTANCE_EXE_B = 'C:\path\build-b.exe'
go test -mod=vendor ./cmd/local -run TestPackagedBuildInstances -count=1 -v
```

该测试验证完整文件摘要、改名副本复用 PID/端口、不同构建并行监听、任务管理器的真实进程名称，以及结束一个版本后独立重启。
